# Monstone「多重幻影」分身退场修复

`Monstone_SC_8` 的四个分身曾在耐久符卡结束后继续存在并发弹。完整推进正常难度 2399 帧后，场上有 4 个分身；第 2400 帧已进入 `Monstone_SC_9`，分身仍存活，随后 60 帧准备阶段额外发出 34 发弹。这是实体拥有关系的遗漏，与符卡倒计时或 JS 后端无关。

分身为了参与自己的接触碰撞和业务绘制而位于 `bullet` 组，但公共普通消弹入口有意排除这种召唤实体。阶段清理只取消普通子弹并回收 `actor` 发射器，因此漏掉了这些不越界、不自然过期的分身。练习模式超时的安静退场分支也不会触发普通清屏。

现在由具体符卡在 `init` 时建立分身列表，保存四次生成的实体引用，在 `end` 时逐个调用现有公共 `Entity.destroy` 生命周期（`kill('phaseEnd')`）。分身立即停止更新、碰撞和后续发弹，尚未进入 World 首次更新的实体同样被回收。已生成的残影继续自然淡出。Bomb 期间分身依然存在；练习超时的普通弹幕仍按原框架退场，不为了清理分身而改变全屏消弹规则。

这个内容生命周期归属放在 `games/rushboss/src/monstone.js`，thlib 无需新增 Monstone 分支。源 Rush 的 `BossSpellCardDeriver.h:2805–2807` 中 `EnemyBullet_Monstone::Clean(CLEAN_BONUS)` 也只销毁分身，没有额外爆炸或掉落。其他持续发弹器均为 `ctx.actor`，已经由阶段结束与练习退场路径回收。

重放修订号更新为 9，修订 8 的旧记录会明确拒绝，避免把原先残留弹幕的记录静默播放成不同结果。

验证：

- `tests/rushboss-monstone-clones.test.js` 的 7 项测试在修复前失败、修复后通过：四个难度的完整 40 秒耐久、练习超时、Bomb 中的存活，以及生成前／首个更新前结束的边界。检查了结束当帧回收和下一张符卡准备阶段不再发弹。
- 全部 704 项 Node 测试通过，无失败和跳过。
- `reports/integration-monstone-clones/` 保存 V8、QuickJS 各自 7200 帧通用集成和 1800 帧原生重放报告；两后端均通过。
- 专项原生验证使用 `tools/verify-rushboss-monstone-clones.mjs`：实际应用完整运行自然超时的正常／练习路径，另用已有分身的场景隔离超时前、超时当帧、下一卡准备及练习离场的画面。GPU 场景仅将倒计时移至终点，具体范围记录在输出报告，不能作为整张符卡的原作逐像素对照。
- `reports/rushboss/monstone-clones/report.json` 专项验证通过：两后端各完成正常和练习的完整 40 秒自然超时，四组 GPU 截图（8 张）和状态分别完全一致，关键图片已查看。第 2400 帧实体数从 4 变为 0，此后发弹总数保持不变；残影短暂保留后自然淡出，没有活动分身留到下一张符卡。

本次未修改引擎二进制或公共 thlib，默认 SDK 不包含 Rush Demo，因此无需重打包 SDK。
