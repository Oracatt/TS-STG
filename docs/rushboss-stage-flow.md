# RushBoss 关卡交接、对白退场与音频恢复

本次依据只读 `Touhou20Reconstruction/source_reconstruction` 和导出的 ANM/MSG，对公共框架及其 Rush 应用接入进行修正。原游戏可执行文件没有运行；以下是源码、动画数据及本引擎原生输出的验证记录，不宣称整局与原作逐像素一致。

## 公共与业务边界

- `TouhouDialogue` 的 `exit:'beforeBoss'/'afterBoss'` 保留原 30 帧立绘退出。战后退出第 1 帧交接结算，第 31 帧才完成并允许释放对白。文本和气泡按源 MSG 清理路径处理，不另外添加源程序没有请求的气泡淡化。
- `TouhouStageClear` 使用公共 `front:111` 的 STAGE CLEAR 图像和原 ANM，120 帧后接受新的确认输入，300 帧自动结束；结束时请求 2 秒 BGM 淡出，10 帧后进入下一场景。魔石统计与计分公式不进入公共包，奖励和统计行由使用方注入。
- `TouhouStageTransition` 以背景优先级 10 实现 30 帧黑色覆盖、30 帧揭幕。HUD 保持可见；覆盖时旧背景继续运动，自机主体隐藏、僚机执行原退出动画，自机逻辑暂停，并清理旧道具和活跃 Bomb。完全覆盖后交接关卡，继承位置、残机、Bomb、Power、分数和碎片，揭幕期间下一关继续更新。
- `TouhouMusicFade` 和 `touhouMusicVolume` 提供公共音量曲线与固定帧淡出。新增底层 `setMusicVolume` 只调整增益，不改变游标或暂停状态。曲目、路径、循环点仍由 `games/rushboss/src/music.js` 管理；thlib 不包含任何游戏 BGM。

公共 API 详见 [关卡交接](touhou-stage-flow.md)、[对白](touhou-dialogue.md)、[自机换关](touhou-player-stage-visibility.md) 和 [音乐](touhou-music.md)。标题进入游戏仍使用现有 `TouhouSceneTransition`；普通关卡交接使用独立的背景过渡。公共 owner 的时序可配置；默认 30+30 帧是确定性的源风格模型，不把原程序异步加载的调度边界作为确定帧数宣称。

## 修正与核查结果

退出到标题、开始新局、重新挑战和重用已缓存曲目时，音乐显式 `stop → seek(0) → play`。对白与战斗连续请求同一首曲目则维持连续播放。暂停恢复、选项中的音量调整使用独立的控制接口，不能借由重新 `play` 修改音量。

原符卡开始使用 33 号音效 `se_cat00.wav`，触发点属于 `TouhouSpell.begin`。实际 Rush 音频队列与公共素材测试确认 16 张符卡均只播放一次该音效，正常非符转符及独立符卡准备时间也有覆盖，未发现需要补发的宣言音。已将原先线性的 BGM 音量设置换成原作曲线：默认 70 对应约 0.596 的线性增益；音效继续使用其独立曲线和原 -900 衰减。验证针对事件、素材及音频调用，并非听感验收。

消弹时曾遗漏退场弹体自身的大小、透明度与染色，使缩小的弹体突然变回 1 倍。现在退场和活动弹体共用绘制参数。独立碎片仍按源 ANM 大小绘制，不随弹体缩放，也没有整体缩小特效。尺寸及逐帧数据依据见 [消弹核查](rushboss-combat-restoration.md#消弹尺寸核对2026-10-04)。

关卡时序会改变确定性状态，因此 Rush 重放修订号从 7 升到 8，旧修订明确拒绝，避免静默播放出不同结果。

换关的持久记录也补齐了点道具价值、点道具拾取数量及奖励残机计数，防止新关卡重建自机时回到初始值。暂停和换关不会误改这些累计记录。
