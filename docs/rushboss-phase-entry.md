# 独立符卡开始前的等待

普通非符转配对符卡，和旧符卡结束后进入独立符卡，是两条不同的原作脚本路径。伤害处理在同一帧执行下一个脚本，不意味着脚本中的所有等待都可以省略。

用户指出的一面第二张符卡转第三张符卡，来源为只读目录 `D:/AIWorkspace/Touhou20Reconstruction/scripts/recovered/ecl/st01bs.ecl.txt`：

| 相对击破帧 | 动作 | 来源行 |
| --- | --- | --- |
| 0 | `BossCard2` 的阈值跳转到 `Boss3`；设180帧保护和2500 HP | 637、420–421 |
| 0 | 消弹、掉落、结算旧符卡，清理旧攻击 | 422–452，结算为439 |
| 0–90 | 使用插值模式9移到 `(0,128)` | 453 |
| 0–160 | `ins_23(160)` 等待；玩家、世界、保护计时和结果演出继续更新 | 455 |
| 160 | 调用 `BossCard3`，这时才开始新符卡名、SpellCardAttack 和新符卡计时 | 456、815–833 |

`enemy_damage.cpp:21–24` 在伤害处理中立即运行下一脚本。`ecl_vm/vm.cpp:183,219` 的 VM 在遇到 `ins_23(160)` 后把局部时间减160，后续每帧先检查时间是否达到指令时刻，再加一并等待。因此击破帧记为 **t0**：t0 结束时局部时间为−159，t159结束为0，t160执行新卡。`enemy_update.cpp:72–83` 在脚本和伤害后扣除保护计时，因此180帧保护在 t0结束为179、t159结束为20、t160开卡前为20、t160结束为19。160帧保护在 t159结束已经为0。

## Demo 的数据边界

私有 [`boss-phase-entry.js`](../games/rushboss/src/boss-phase-entry.ts) 选择与当前 HP 映射一致的四个包装：

| Demo 下一阶段 | 原作包装 | 完整保护 | 等待 | 卡开始时剩余保护 |
| --- | --- | ---: | ---: | ---: |
| Sunny 7 | st03 Boss4 → BossCard4 | 180 | 160 | 20 |
| Monstone 9 | st04 Boss4 → BossCard4 | 180 | 160 | 20 |
| Artia 12 | st06 Boss6 → BossCard6 | 160 | 160 | 0 |
| Artia 13 | st06 Boss7 → BossCard7 | 160 | 160 | 0 |

表中最后一列是 t160 执行新卡前的值。所有包装都有90帧、模式9的归位移动。Artia 12 前面虽然是 Rush 多出来的非符，当前原作血量映射选用的仍是独立 `Boss6` 包装；不能只检查相邻两阶段是否都有符卡名来选择等待。

公共 [`TouhouBossPhaseTimeline`](../packages/thlib/src/touhou/boss-phase-timeline.ts) 提供固定帧等待和事件时钟。具体 Boss、阶段编号、原作行号及移动目标是 Demo 数据。进入包装时建立下一血组和完整保护，让归位、玩家与结果动画继续运行；等待结束后才启动新符卡和弹幕初始化。不要先调用 `beginSpell` 再冻结画面，也不要只扣除160保护而省略160帧实际等待。

单卡练习和命令行直接指定某张卡的入口，直接进入所选 `BossCardN`，跳过普通通关路径的包装。原作普通非符转配对符卡继续在同一帧进入，并保留共用血环。新非符自身的准备和第一发弹幕时间见 [阶段切换节奏](rushboss-phase-rhythm.md)，不能拿这个160帧等待替换那套准备时序。

来源数据由 [`rushboss-phase-entry-source.test.js`](../tests/rushboss-phase-entry-source.test.js) 核对实际 ECL 行、操作先后、原作一面对应路径和现有 HP/保护映射。该测试不启动原作程序。
