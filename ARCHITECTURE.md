# TS-STG architecture / implementation contract

TS-STG has three layers: a C++17 low-level host, the portable ECMAScript library `@ts-stg/thlib`, and applications. All STG rules are authored in TypeScript and run as portable JavaScript. thlib owns reusable mechanisms, restored common characters/weapons/Bombs and their common materials. A resource's source game does not make it exclusive to that game. Only genuinely title-specific rules, variants, layout, artwork, music and stages stay in the application; for example, TH20 magic-stone variants are excluded from the shared baseline. Windows first; CMake + raylib + V8 / QuickJS-NG. The engine and procedural demo require no original game binaries/assets. The restored presentation uses the curated local common resource pack. `games/touhou20/` and `games/rushboss/` are private demos depending on thlib, never the reverse. The public restored entry is `@ts-stg/thlib/touhou`; there is no `@ts-stg/thlib/th20` entry.

## Host ABI v1

Entry module sets `globalThis.__tsstg_game = { update(inputMask), render(), snapshot?() }`.
Host uses fixed 60 Hz updates; `render()` returns an array of drawing command arrays. Logical canvas 960x720. The host never knows about bullets, player, boss, score, stages, or menus.

Audio transport and gain are separate platform services. `tsstg.setMusicVolume(id,volume)` accepts a loaded stream and finite gain in `[0,1]` without changing playback or pause state. Fade timing and curves remain in JS. Headless execution validates the same arguments without opening an audio device.

Input bits: LEFT=1 RIGHT=2 UP=4 DOWN=8 SHOOT=16 BOMB=32 FOCUS=64 PAUSE=128 CONFIRM=256 CANCEL=512. Z maps SHOOT|CONFIRM; X maps BOMB|CANCEL; Enter CONFIRM; Esc PAUSE. JS derives edges. Headless execution supplies the exact mask, no implicit input.

Commands (colors are unsigned packed 0xRRGGBBAA numbers):
`['clear',color]`, `['circle',x,y,r,color]`, `['ring',x,y,inner,outer,color]`, `['line',x1,y1,x2,y2,width,color]`, `['lineStrip',[[x,y,color],...]]`, `['point',x,y,color]`, `['rect',x,y,w,h,color]`, `['text',text,x,y,size,color,fontId?]`, `['triangle',x1,y1,x2,y2,x3,y3,color]`, `['scissor',x,y,w,h]`, `['scissorEnd']`, `['sprite',id,x,y,w,h,rotation,color]` (center origin, radians), `['spriteRegion',id,sx,sy,sw,sh,x,y,w,h,rotation,color]`, `['blend','alpha'|'add'|'multiply']`, `['blendEnd']`.

Generic mesh/compositing commands: `['mesh',textureId,[[x,y,u,v,color],...],triangleIndices]` (texture0 means white), `['targetBegin',id,clearColor]`, `['targetEnd']`, `['blendFactors',src,dst,operation,srcAlpha,dstAlpha,alphaOperation]`, `['sampler',id,filter,wrapU,wrapV]`. UV is top-left for ordinary textures and render targets. Scissor/blend/target must be balanced, do not nest within the same kind, and cannot cross target boundaries. Sampling the active render target is rejected. See [native API](docs/native-api.md) for complete resource and pixel ownership rules.

`['mesh3d',textureId,[[x,y,z,u,v,color],...],triangleIndices,mvp16]` uses a JS-supplied column-major OpenGL clip transform with GPU perspective-correct interpolation. This is a generic platform primitive; camera and original projected-animation rules stay in JS.

`['quad',id,corners8,x,y,scale,offsetX,offsetY,u0,v0,u1,v1,color0,color1,color2,color3,pixelSnap]` expands a local four-corner mesh with a generic binary32 translation/scale and optional half-pixel alignment. Its CPU implementation preserves explicit rounding and reuses mesh submission. JS resolves animation rules, local rotation, inherited transforms, UVs and colors before issuing this primitive. This avoids allocating and projecting four temporary JS vertex arrays per sprite without moving STG logic into C++. Custom adapters without `quad` retain the ANM `mesh` path; the numeric and graphical equivalence tests compare both paths.

`['statefulQuad',...quadFields,state]` uses the same geometry with an immutable ten-field drawing-state array `[cutoff,src,dst,operation,srcAlpha,dstAlpha,alphaOperation,filter,wrapU,wrapV]`. Its exact expansion is `alphaTest(cutoff)`, `blendFactors(...)`, `sampler(id,...)` for a nonzero texture, `quad(...)`, `blendEnd()`, `alphaTest(0)`. It preserves sprite order and overlapping blends, and leaves the sampler installed. thlib resolves the state and animation entirely in JS. The native host validates and submits the generic rendering primitive. ANM adapters with `quad` but without `statefulQuad` retain the expanded six-command path.

`['alphaTest',cutoff]` sets a generic fragment-alpha threshold in [0,1]; 0 disables it. The renderer discards fragments below the threshold after texture and vertex color multiplication, before blending. The state starts disabled every frame. The final logical canvas is copied to the window as opaque RGB; intermediate targets and pixel readback retain RGBA. STG-specific blend/threshold choices remain in thlib.

`createShader(fragmentSource,vertexSource?)`, `['shaderBegin',id,uniforms]`, `['shaderEnd']` and `unloadShader(id)` provide caller-owned GLSL330 programs and balanced drawing scopes. Uniforms carry generic typed values; no game-specific shader is embedded in native code. Implicit alpha testing must be disabled within custom scopes. `sampler` also supports `anisotropic4x`. Windows `createTextLayout` / `rasterizeTextLayout` / `destroyTextLayout` use the system font collection, DirectWrite shaping and actual Direct2D glyph-outline strokes. Returned raster textures have explicit ownership and do not include redistributed system fonts. Full contracts and validation limits are in the native API document.

Native global `tsstg` is declared by `packages/thlib/src/native-host.ts`: generic texture/target creation, RGBA readback/update, explicit unload methods, sound pan/loop/stop, streamed music loop regions/seek/time, Unicode font loading, and project-scoped file access. Resources resolve under project root. ESM supports relative paths and the public `@ts-stg/thlib` root and module subpaths, including `@ts-stg/thlib/touhou` and `@ts-stg/thlib/touhou/player`, resolved from packages/thlib/src or the project's node_modules package. Applications use relative imports for their own modules. An external installed thlib source directory is separately scoped for module reads only. File access rejects path traversal. Runtime failures propagate with stack traces and nonzero exit.

CLI: `ts-stg [entry.js] [--root path] [--backend auto|quickjs|v8] [--headless] [--frames N] [--input mask] [--snapshot path] [--screenshot path]`. Default entry is the consumer project's main.js relative to root, with no dependency on a demo. Repository launchers explicitly select demos for local development. Headless invokes update/render and validates commands without opening window/audio. Frame limit also works graphically for smoke testing. The backend-neutral C++ interface keeps runtime types outside thlib. Windows x64 builds embed V8 and QuickJS-NG, with auto selecting V8. V8 uses its own context and scoped ESM resolver, not a Node.js environment; all STG logic and original animation arithmetic remain in thlib. QuickJS-only builds are supported through `TSSTG_ENABLE_V8=OFF`.

Optional `--profile path.json --profile-warmup N` separates script, decoding, CPU/GPU drawing, presentation wait and instrumentation timings. `--benchmark --frames N` renders one fixed update per frame without intentional pacing; ordinary play still uses the fixed 60 Hz accumulator. Benchmark and headless numbers must not be described as normal-play frame rates.

## TypeScript source and runtime modules

Core modules: packages/thlib/src/{math,input,task,world,bullets,lasers,patterns,render}.ts. Exports include `RNG`, `Input`, `Keys`, `TaskRunner`, `wait`, `World`, `Entity`, `Bullet`, `Laser`, `Patterns`, `DrawList` and geometry helpers.

Gameplay modules: packages/thlib/src/{player,enemy,boss,items,effects,stage,menu,replay,game}.ts. `index.ts` re-exports the implementation and shared contracts; declarations are generated from this same source. Game exposes `update(mask)`, `render()` and `snapshot()` for native hooks, and reusable APIs for external consumers. `animation.ts` and `resources.ts` supply sprite animation, tweening, projection and an injected-host resource cache.

The compiler checks strict portable ES2022 with no Node/DOM ambient types in thlib. It emits `dist/**/*.js`, `.d.ts` and maps. Both embedded runtimes load only `dist`; they do not interpret TS syntax. Imports keep `.js` ESM specifiers in TS source. Examples, demos and editor also use TS, with generated sibling JS to preserve native entry paths. Existing JavaScript consumers remain supported. C++ stays the native platform layer; JS regression fixtures and maintenance tools may intentionally remain JS. See [TypeScript workflow](docs/typescript.md).

examples/danmaku contains application code and native adapters. CMakeLists.txt and native/ contain the platform host and dependency integration. The root build/run/package scripts and tests exercise both layers.

`float32.js`, `repeating-input.js`, `layered-render.js`, `grid-mesh.js` and `radial-distortion.js` provide reusable binary32 arithmetic, configurable input repeat, stable ordered drawing and mesh deformation. They have no game resource IDs, viewport offsets or layer tables. `SpriteAtlas`/`SpriteClip` consume named-rectangle/frame manifests with injected resource adapters. `assets/reference-common` supports that lightweight presentation API. `assets/touhou-common` contains the curated common ANM animations, character and projectile images, effects, minor enemies, bitmap font and sounds used by the restored modules. Mixed atlases retain only common pixels; excluded scripts/sprites reject access. Provenance, source hashes and resource notices are separate from the MIT code license.

`packages/thlib/src/touhou/` owns the restored ANM interpreter/projection/registration rules, common character, shot, Bomb, bullet, laser, item, enemy, spell, damage, font, audio and effect implementations. `TouhouPlayer` consumes normalized baseline weapon data (`ts-stg-touhou-shots`, patterns 0..14) rather than reading a title-specific binary. `createTouhouResources(host, {basePath})` loads the curated pack through an injected host; without one it supplies the same weapon/style data for headless simulation. Actor-owned animations advance with their owners; consumers advance detached animations separately and release shared resources through the resource owner.

`spell-presentation.js` also supplies optional configurable perspective cameras/sprites and textured rings, retaining homogeneous clip W and the configured segment count. `assets/spell-common` retains additional ordinary attack-line, aura and charge skins. These are optional customization facilities; the restored default uses the source ANMs described below. Former RushBoss shader/title/ring implementations remain under games/ for historical comparisons. See [LuaSTG / THlib design review](docs/luastg-reference.md) for the upstream commits and adopted design decisions.

`TouhouApplication` owns title → difficulty/character selection → game → pause/results → retry/title. `TouhouGame`, `TouhouHud`, `TouhouTitleMenu`, `TouhouPause` and `TouhouGameOver` live in public thlib. Host pixel/audio services, game stages and menu skins are injected. Fresh scene banks own mutable animation state and dynamic surfaces; static textures share the resource owner's cache. Unimplemented menu actions are disabled by default; a consumer can provide handlers and skins.

`TouhouBossPresentation` composes the original effect 99/108 entrance aura, effect 6 → 4/5 double circles, effect 13 SpellCardAttack, original front/ascii countdown and health indicators, text 22/23 names, and `TouhouEnemyDistortion`. Canonical Boss radius is 160; midboss radius is 128. The original 17×17 mesh, 32-segment circles and ten opening strips are the shared default. RushBoss adapts its coordinates and phase outcomes to this owner; its former 125% warp shader and replacement rings are no longer the default. Specific portraits, card backgrounds and attacks remain the demo's responsibility. Shared charge ANM opcode 508 invokes the JS `TouhouConvergingParticles` controller and original Hermite trajectories.

`TouhouTextRenderer` restores CP932 centering, original font selection, GDI bitmap outlines/crop/alpha and dynamic text ANM in JS. Native exposes generic font probing, encoding, raw bitmap text rasterization and texture-region updates. It contains no spell or font-profile rule. Dynamic surfaces are isolated per entry and bank, including entries with identical names.

`games/touhou20/src/` supplies only its private title/background artwork, music, authored stage composition and TH20 SHT binary importer. Old common names re-export the same public classes. The simpler `Game`/`Player`/`Weapon`/`Bomb` APIs remain available for custom games; they are not substituted for the restored APIs in either demo. `examples/touhou-framework` demonstrates the complete shared composition without importing games/. Current supported operations and unresolved equivalence limits remain documented in the fidelity reports.

## Local packaging

Only the native engine and thlib are release products. `package.ps1` creates `dist/TS-STG` from an allowlist: executable, packages/thlib, generic SDK/API documentation and licenses. It excludes games/, examples/, tests/, tools/ and title-specific assets. Run.cmd expects the user's main.js; it is not a game launcher. `package.ps1 -WithReferenceAssets` creates a separate `dist/TS-STG-local` with the local games/touhou20/ demo and resources, and Play.cmd selects its main.js. This is a private development/demo artifact and must not be published. The npm thlib package contains only src/ and common assets/ plus its own metadata/docs/license; it never includes game source or title-specific artwork/data. Curated common visuals retain their original resource provenance and license notices. The reference demo's private package flag prevents accidental npm publication.

Each package is assembled in a new staging directory. Existing output is moved intact to a unique `.previous` directory only after assembly succeeds; user edits/saves are preserved and stale assets cannot contaminate a fresh generic package. Packaging performs no recursive deletion and rejects output junctions/symlinks. The native executable defaults to the consumer project's main.js. Workspace Play.cmd explicitly selects the generic demo; Play-TH20.cmd explicitly selects the reference demo. Neither demo is part of the release SDK.

Coordinates: radians, +x right, +y down, speeds units/frame. The generic World's playfield default is `{x:32,y:24,width:576,height:672}`. Restored `TouhouPlayer` defaults to `{x:-192,y:0,width:384,height:448}` and projects through an explicit view. It accepts `bounds`, `movementInsets` and respawn coordinates; its shots, Reimu Bomb boundary behavior and items use that configured field. RushBoss translates its source Y-up coordinates into this Y-down API. Simulation updates use integer frames and seeded random streams. Entity spawning/removal is deterministic and safe during iteration. Generic and restored bullet APIs retain their documented contact/graze policies. Pausing must freeze simulation.
